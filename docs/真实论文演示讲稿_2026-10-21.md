# 研证：从问题到可追查证据

建议5—7分钟，非实测效率。两篇源论文已用于本地开发者走查；模型输出不固定。

## 1. 提出研究问题

操作：选择 Layer Normalization（1607.06450v1.pdf），输入：Layer normalization batch size 1 pure online regime。

讲解：我们先验证一个具体判断：batch size 为 1 时能否使用层归一化。

## 2. 检查回答要求

操作：展开回答核对清单和相关回答，点击原文入口；尝试“补问：批大小”，核对原问题和当前论文范围后再决定是否发送。

讲解：有相关词语不代表已答全。系统将明确要求摆出来，让遗漏更容易被发现。

## 3. 保存第一篇证据

操作：定位 PDF 第 2 页关于 pure online regime with batch size 1 的原文，保存证据笔记；记录单样本条件，不写任意任务都更准。

讲解：观察与原文一起保存，页码和版本可以追查。

## 4. 检查第二篇的机制

操作：切换 On Layer Normalization in the Transformer Architecture（2002.04745v2.pdf），查询 Post-LN Pre-LN expected gradients at initialization warm-up，核对第 1 页并保存笔记。

讲解：另一篇讨论归一化的位置、初始化梯度与warm-up；不能把两篇的结论互相代替。

## 5. 建立有边界的对照

操作：在证据笔记选择两篇来源建立边界对照。查看比较前检查，点击补齐研究对象；检查数据、指标、条件和限制还有哪些空格。

讲解：不会因为同样叫LayerNorm就直接比较。格子填满、单位相同，都不能自动证明科学可比。

## 6. 把缺口变成待办

操作：新建包含两篇论文的研究项目，在对照表选择项目，从实验条件空格加入补查，选择本篇原文并回填batch size 1条件。

讲解：未找到证据就保留待补查；真实实验条件有出处后再回填，处理历史会保留。

## 7. 交付可追查的研究资料

操作：导出项目 ZIP、对照 Markdown 和回答成果。打开文件核对来源、清单、待补项及回填历史。

讲解：交付的是可继续检查的研究过程，模型的一次回答只是其中一步。

## 8. 展示失败与边界

操作：展示上一轮Pre-LN／Post-LN更新次数互换的失败记录和拒绝实验；指出复杂机制漏答仍未全部解决。

讲解：系统已增加有限数字归属防护，但不宣称零幻觉。当前是开发者验证，没有真人省时或满意度结论。
