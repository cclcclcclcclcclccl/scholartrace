## 已采用的改进

- 部分回答会显示未进入最终答案的候选条数。即使已有回答，也能打开候选原文、单独追问。未采用候选可能是核验未通过或去重，不能直接视作错误事实。
- 使用说明同步解释“有回答不代表完整正确”。候选数量仅反映本轮生成与保留差异，不是缺失知识总数或置信度。
- 浏览器实测发现并修复 Markdown 导出丢失部分回答说明的问题：导出现在保留遗漏说明、候选论文标识、页码和原文块编号。来源仍标注“未经支持性确认”。
- 新增冻结协议工具、失败案例台账和发布检查。旧题退步、完整性下降、无据论断增加、虚构实验收到答案都不能通过；缺少逐条审查、引用未核对、模型调用失败或记录不完整也不能算通过。
- 发布检查读取每次模型调用轨迹，避免接口吞掉超时并降级为原文检索后被误算为正确拒答。
- pytest 仅收集 `tests/`，避免已解压的交付源码副本重复参与测试。

## 如何使用

1. 在阅读台选择论文，输入复合问题并按 Enter 发送。例如分别询问数据集数量和对比基线数量。
2. 展开“逐项回答情况”。“有回答”只说明有论断通过初筛，仍需检查是否漏掉所问字段。
3. 如果提示有候选未进入最终回答，点击“查看候选原文”跳到对应PDF页；候选本身不等于已确认答案。
4. 点击“单独追问此项”，原子问题会填入输入框并保持文献范围。由你检查后再发送，不会自动触发重复请求。
5. 在任务与成果中重新打开回答，或导出Markdown，遗漏说明与候选出处会保留。模块旁的帮助按钮可随时查看说明。

## 可复用改进流程

先冻结问题和代码，再运行，不允许看到结果后改题或预期。新增问题应优先来自未使用过的论文，并覆盖单位、对象、实验条件、反事实与无法回答情形。

```powershell
.venv/Scripts/python.exe scripts/freeze_quality_iteration.py --source-protocol evaluation/proof_v6_qa/protocol.json --target-dir evaluation/my_candidate --notice "开发回归，非独立评价"
.venv/Scripts/python.exe scripts/run_proof_v1.py --protocol-dir evaluation/my_candidate --output-dir artifacts/my_candidate
```

逐条核对最终答案与完整引用，保留失败和额外论断，按既有格式写 `agent-source-audit.json`。审核标签仍需人类独立复核，不能让模型给自己打分后自动更新生产系统。

```powershell
.venv/Scripts/python.exe scripts/quality_release_gate.py --before artifacts/proof-v6-qa --after artifacts/my_candidate --protocol evaluation/proof_v6_qa/protocol.json --output artifacts/my_candidate/release-gate.json
```

新增题应分别先跑旧版与候选版，再对比。存在退步返回非零退出码；记录无效也停止。发布检查通过仅代表在所测范围没有观察到指定退步，不能证明全局可靠。每个候选的代码、模型、题目、调用轨迹与审查结果必须绑定保留。

## 仍未解决
