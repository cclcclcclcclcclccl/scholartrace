# 混合 PDF 与逐页文字检查

本轮在 v20 问答版本上改进 PDF 导入和 OCR 的完整链路。主站仍为 http://127.0.0.1:8765/ 。本轮不是新一轮模型问答准确率测评，v20 的 27 题结果属于之前的固定开发回归。

## 修复与功能

- 旧流程只有整份文档都缺少文字时才自动 OCR。新导入的混合 PDF 只要存在缺字页，就进入 OCR 队列；其状态显示“部分页需核对”。开放全文下载也走相同判断。已有原生文字块保持不变。
- 空白页没有识别结果时，字符统计归零，避免 SQL 求和得到 NULL 导致写入失败；该页保留“未识别到文字”，不冒充识别完成。
- 文献管理新增逐页文字覆盖检查，区分原生文字、OCR 文字、文字需核对、待识别和未识别到文字。默认展示问题页，可切换全部页、刷新、导出 JSON、跳转原 PDF 页。
- 旧文献即使曾标记 text_ready，检查仍根据实际文字块计算缺口；不会批量改写已有数据库状态。
- OCR 重试保留已保存的 OCR 块，防止引文和笔记来源悄悄变化；未识别页仍可再次尝试。界面内置使用说明。

## 操作方法

1. 打开主站，进入“文献管理”，找到论文并点击“详情”。
2. 在“逐页文字覆盖检查”中看需核对页；点击“查看原图”判断其是否空白、图表或未识别正文。
3. 对缺字页点击下方“识别扫描文字”。任务结束后返回并点击“刷新文字检查”。新上传的混合 PDF 会自动提交 OCR。
4. 需要保留检查记录时点击“导出文字检查”。报告仅含逐页文字情况，不含论文正文。

- 后端最终测试结果见 `artifacts/parsing-quality-20261020/tests-final.log`；新增八项覆盖混合上传、重复上传、纯文字索引、空白页、OCR 保留、旧状态、账号隔离及下载分流。
- 实际 RapidOCR 识别受控三页 PDF：第一页原生文字、第二页扫描正文、第三页空白。第二页识别出原文中的 48 samples；第三页保留未识别状态，未崩溃。重复处理保留原 OCR 块，坐标位于原页面边界内。
- 六项真实浏览器检查通过：实际上传触发 OCR、问题页/全部页切换、导出与接口一致、教程和刷新、390px 无整页横向溢出、问题页跳转原 PDF 第三页。桌面和手机截图已检查。
- 前端 TypeScript 检查与 Vite 构建通过；仍有原有的大分块提示。新增 Python 文件静态检查通过；涉及的旧文件仍有 27 条既有静态检查项，经与 v20 源码逐条比较，没有新增检查项。此处不声称全仓静态检查零问题。
- 验收运行在独立文献数据库和账号库中；主站七张核心表用逐行摘要及 SQLite 完整性检查核对。正式判定及交付内容以 `release-selection.json` 和文件 SHA-256 清单为准。

## 适用边界

文字覆盖检查不是 OCR 正确率或全文语义完整度测评。20 字符阈值与 0.8 OCR 平均置信度仅用于筛出需核对页。含有较多图注或隐藏文字层的页面可能仍有正文未识别；复杂多栏、跨页表格、公式和模糊扫描仍需原图核验。高置信度也可能识别错。

本轮实际 OCR 是受控英文样例集成验证，不是独立论文库识别基准。已保存 OCR 文字暂不支持直接覆盖更正，以保护旧引文；更正与引用迁移需要单独设计。历史文献不会在升级后自动批量 OCR，可通过面板检查后手动发起。

模型权重、问答生成和复核核心文件沿用 v20；本轮没有重新运行 27 题真实推理，因此不将之前的成绩计为本轮新增结果。独立人测、广泛的新论文盲测、公网演示、最终 PDF/视频同步和官方提交仍未完成。

## 文件

- `backend/document_quality.py`：只读逐页检查。
- `frontend/src/DocumentQuality.tsx`：检查面板、原图入口和操作说明。
- `tests/test_document_quality.py`：隔离回归。
- `scripts/verify_document_quality.py`：真实 OCR 样例与隔离演示。
- `scripts/check_document_quality_ui.mjs`：真实浏览器验收。
- `output/parsing-quality-20261020/`：独立源码包、证据包、说明与校验清单；不含私有数据库、账号库、模型权重或真实论文 PDF。
