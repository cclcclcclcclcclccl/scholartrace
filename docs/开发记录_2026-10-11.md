# 第一阶段开发记录

日期：2026-10-11。参赛者：蔡晨霖。代码由 AI 根据用户目标与反馈协助编写。

## 用户输入与关键选择

- 用户提供压缩包并要求立即开始实施，逐步解释每一步。
- 用户强调方向可不大众化，但质量必须很高；授权 AI 确定方案后直接推进。
- 沿用技术预算为 0 元的限制。选择研究证据更新审计，保留完整科研助手的后续建设范围。

## 实际完成与故障修正

1. 检查并解压 RAR，原始文件保留；读取赛项 PDF 的完整文字，并渲染图片形式的提交要求和评分表。
2. 发现两套评分差异，保留来源并建立核对说明，没有自行认定最新规则。
3. 建立项目内 Python 环境、React/TypeScript 前端、FastAPI 后端、SQLite 文献/证据存储及可重复执行脚本。
4. 受限进程联网超时，使用通过审批的项目依赖安装完成环境；未订阅或调用付费服务。
5. 下载 Qwen 官方公开量化模型和 llama.cpp 官方发布程序，核对文件大小与 SHA-256；在本机 GPU 上启动。
6. 逐页检查资料，导入 39 份测试 PDF；对扫描版单独运行 RapidOCR，保留 PDF 坐标和原件。
7. 首轮发现 arXiv 旋转边栏被识别为标题，修正横向标题和 small-caps 行聚合；GPU/GPUs 词形导致关键证据漏排，修正词干与显式关键词排序。
8. 浏览器发现 Windows 把 `.mjs` 当作 `text/plain`，导致 PDF.js worker 无法执行；修复响应类型，并加入真实静态资源回归检查。
9. 本地模型把“未提供价格”重复附上多个无关引文，改为证据不足状态并去重，避免把缺失信息声明冒充正向支持性论断。
10. 真实版本复核中，模型比较能区分硬件段落的改写与代码公开状态变化；发现 PDF 跨行网址触发引文校验，实施限定 URL 换行归一化并测试数字空格保持不变。
11. 桌面/手机尺寸截图检查后补充手机文献选择器；真实浏览器交互检查通过。

## 实测产物位置

- `artifacts/inspection/corpus-manifest.json`：文件来源、逐页状态、页数与哈希。
- `artifacts/inspection/ocr-report.json`：扫描件每页耗时、行数和 OCR 自报置信度；置信度不是准确率。
- `artifacts/inspection/local-model-smoke.json`：问题、实际回答、出处、耗时和运行模式。
- `artifacts/inspection/real-version-audit.json`：旧/新版原文、文本基线、模型比较及引文校验结果。
- `artifacts/browser/results.json` 及页面 PNG：实际界面操作检查。
- `artifacts/environment/`：公开模型/运行时来源元数据与校验记录。
- `artifacts/runtime/`：服务日志和本次启动的进程编号。

代码中的提示模板见 `backend/app.py` 与 `backend/review.py`，其修改通过 Git 留痕。当前记录是阶段摘要及本地模型小样证据，不宣称已整理完整比赛所需的全部 Prompt/协作对话审计附件。

## 当前限制

词法检索和少量语义比较只是第一阶段基线；全量作者/公式/表格结构化、完整语义检索与重排、动态任务规划、全文翻译、外部检索推荐、图谱与写作、公网部署及正式验收集均需继续完成。模型输出的引文可核验存在，不能据此宣称所有语义推断已获得证明。
