# 多篇逐项问答与追问验收

本轮在研究项目工作区之后，继续改进多篇科研问答的覆盖、来源隔离和追问操作。保留本机 Qwen3-4B 与既有检索模型，没有接入付费 API，没有修改原 PDF，也没有把开发回归当作官方成绩。

## 用户可见的变化

- 多篇复合问题按每篇论文列出原始子问题，明确哪些项有通过初筛的回答、哪些项仍未解决。没有检索结果、处理失败或超过本轮逐篇预算的论文，也保留对应问题及原因。
- 模型改写只用于检索词，不再用改写结果替换用户问题。不同论文的结果仍分别绑定实际版本、页码和原文。
- 回答按论文展示为纵向卡片，先显示回答和原文入口，再显示逐项状态；支持片段可展开。表格答案增加直接核对表头／表题入口。
- 未解决项提供“单独追问此项”。点击后带入原句和所属论文范围，保留上次回答，用户可以修改后按 Enter 发送；按钮不会自动请求模型。项目内追问继续关联原项目。
- 在单篇模式，追问使用上一回答提交时的明确范围；全库模式没有明确来源集合时不提供这个快捷入口。它不是跨轮对话记忆，请把指代和限定条件补完整。
- 对于不同子问题的相似回答，去重不会把其中一项直接删掉，避免覆盖统计失真。这不等于已经解决所有语义重复。

## 具体修复

1. **多篇分支原先关闭子问题拆分。** 每篇递归调用使用 scoped 模式，原实现只对非 scoped 模式拆分子问题。现保持原句分项，检索和审核仍限定当前论文。范围外的提问未找到本篇支持时显示未解决，不把其他论文的答案搬进来。
2. **预审去重和后处理没有保留子问题身份。** 现在去重隔离论文、文本块、子问题；数值、模型变体和条件保护沿用原规则。相同结论来自不同子问题时分别保留，是否通过支持检查仍逐项决定。
3. **某篇异常可能让整次多篇问答退回检索模式。** 新增逐篇异常边界，保留其他论文已得到的结果；失败篇给出可重试状态，不把失败解释为论文未报告。
4. **输入输出示例压过能力定义。** GPT-4 报告附录中大量 prompt／response 示例占据候选列表。新增双语输入／输出概念检索，优先保留同段明确描述接受输入、产生输出的正文。规则不包含 GPT-4、ViT 名称或答案数值；只能返回当前范围内的真实文本。单元测试使用虚构传感器模型验证同一通用规则，模型输出仍需支持性复核。
5. **同名不同版本的导出难辨别。** 汇总逐项状态包含原文件名和文献 ID，Markdown 中可区分 v1／v7，不再只重复同一论文标题。

## 冻结开发题与实际结果

`tests/acceptance_questions_v6.json` 在第一次调用前保存，两道题均由开发代理围绕已知主题编写，后续未改评分条件；不属于独立测试集。所有输出、引用和耗时保留。模型生成与审核使用同一本地模型，存在相关错误。

| 问题 | 修改前 | 修改后的真实观察 | 限制 |
| --- | --- | --- | --- |
| Attention v1／v7：GPU 与 seed 42 单次 BLEU | 约 12.3 秒；GPU 回答也丢失，没有逐项状态 | 约 38.1 秒；两篇分别保留 8 块 NVIDIA P100，未知单次测量均未填入结果，分别显示 Q2 未解决。最终真实浏览器再次验证通过 | 等待增加；未解决不证明论文全局无答案 |
| GPT-4 输入输出与 ViT-Base 规格 | 约 17.0 秒；只有 ViT 规格保留，没有逐项状态 | 中间版本约 49.3 秒，GPT-4 仍漏答；补上定义段检索后约 32.1 秒，GPT-4 图像／文本输入、文本输出和 ViT 12／768／86M 分别保留 | ViT 仍保留部分英文表头表达；每篇不适用的问题仍标为未解决，没有自动语义路由或适用性判定 |

以上两题的机械检查分别达到既定条件；不是新增独立题的大样本准确率，也未比较其他模型。逐句检查中，GPT-4 回答与第一页支持句一致；ViT 三个数值与表格行及表头对应；GPU 回答与两版原文第 7 页一致。

额外尝试过通用存储层级提示，并复查既有 FlashAttention 题。该试验约 66 秒，仍未保留完整的 HBM／SRAM 回答，还出现把原始方法 tiling 描述泛化到稀疏扩展等需要复核的措辞。未证明收益的存储层级提示已经撤回，失败输出保留在 `final-v4-flash.json`；该文件名是当时预定的记录名，实际是未通过的试验，不代表最终功能通过。输入输出题不触发该规则，相关定义检索保留。

## 工程及真实浏览器验收

- 最终后端 **189 项测试通过**，新增保护覆盖 scoped 模式原句分项、不同子问题／论文去重隔离、空结果和超预算篇的状态、单篇异常隔离及通用定义段优先级。
- 前端 TypeScript 与 Vite 正式构建通过。修改的概念检索、论断检查、评测脚本和测试文件 Ruff 通过；Git diff 空白检查通过。仍有原有 Mermaid 分包体积提示。
- `check_multi_question_ui.mjs` 实际使用本地模型和产品 API，在既有项目中提问两版 Attention。没有替换问答响应，验证每篇 1／2 项有回答，候选原文可跳回对应 PDF 页。
- 浏览器先查看另一篇论文，再点击原卡片“单独追问此项”；实际请求仅包含原卡片的文献 ID，项目 ID 保留。点击按钮时未自动发送，上次回答仍在；编辑问题后 Enter 发送成功。
- 真实回答保存为项目成果，可以重新打开，汇总中有 4 条逐项状态；Markdown 导出含两版文件名及未知测量问题。
- 390 px 手机视口和卡片内部均无横向溢出，浏览器无 JavaScript 页面异常。新卡片说明和操作文字为 12 px。桌面／手机截图已查看。
- 初次连续跳转截图截到了 PDF 渲染瞬间。补查等待 `aria-busy=false` 和真实画布像素后，PDF 正常显示，没有据此误报阅读器故障。
- 最后的字号／布局检查使用已记录真实回答的回放，明确标为 **只验证显示、未重新推理**；真实模型集成由前面的浏览器脚本独立验证。
- 浏览器检查前后的 40 条文献、47,872 个文本块、2 条笔记摘要完全一致，268 份已有成果内容保持不变；仅增加 2 份真实浏览器问答成果。SQLite 完整性检查为 ok，网页和模型健康正常。API 评测试验也各自留下原始成果，不删除失败输出。

## 如何体验

1. 刷新 <http://127.0.0.1:8765/>，打开“研究项目 → 注意力机制：版本与效率证据”。
2. 在“研究成果”打开标题为“模型训练用了哪些 GPU？论文有没有报告 base 模型随机种子 42……”的本轮回答，可先检查保存结果，无需重新推理。
3. 从项目点击“使用项目文献提问”，输入上述复合问题；查看两张论文卡片及未解决项。
4. 在未解决项点击“单独追问此项”，检查范围已变成该篇论文，补全或修改问题后再发送。

目前一次选择仍允许最多 40 篇，但逐篇生成预算最多处理前 8 篇，其余明确标记未处理；复合问题最多拆成 4 个原句项，多余部分并入最后一项。前端问答等待上限仍为 120 秒，多篇复杂任务可能达到上限，建议分批。没有宣称这两个限制已解决。
