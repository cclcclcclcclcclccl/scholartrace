# 研证部署与复现

本机主运行环境为 Windows、Python 3.12、Node 24、llama.cpp b11552 Vulkan、Qwen3-4B Q4_K_M，模型上下文 8192。模型运行在 127.0.0.1:8081，应用运行在 127.0.0.1:8765。没有配置付费 API。

## Windows 本机

1. 建立 Python 3.12 虚拟环境：`python -m venv .venv`。
2. 安装锁定依赖：`.venv\Scripts\python -m pip install -r requirements-lock.txt`。
3. 前端：`npm --prefix frontend ci`，然后 `npm --prefix frontend run build`。
4. 按模型安装脚本下载生成模型与多语言检索模型；现有模型在 `models/`，上游来源和校验和分别由安装脚本及模型 manifest 保存。
5. 双击 `启动研证.cmd`。启动器会复用现有项目进程，守护程序在后端异常退出后重启；`停止研证.cmd` 会核验路径及进程创建时间后停止项目服务。
6. 浏览器打开 `http://127.0.0.1:8765/`。无需模型密钥；若模型未就绪，问答返回原文检索结果。

`data/scholartrace.sqlite3` 保存本机空间；`data/accounts/<随机账号 ID>/library.sqlite3` 保存账号独立空间。PDF 上传文件在 `data/uploads/`，访问权限以各空间数据库的记录为准。数据目录、模型、环境变量文件不进入源码仓库。

## 容器配置

提供 `Dockerfile`、`Dockerfile.model` 与 `compose.yaml`。模型容器固定构建 llama.cpp b11552；应用共用其网络命名空间，以便继续使用环回模型接口，避免任何付费或未知远端模型回退。

首次启动前，准备 `models/Qwen3-4B-Q4_K_M.gguf` 和 `models/multilingual-minilm/`。在 Linux 上创建可由 UID 10001 写入的 `data-container` 目录，然后 `docker compose up --build -d`。数据使用独立目录，避免覆盖 Windows 本机 SQLite 中的绝对 PDF 路径；需要通过应用重新导入文献。

公式组件：本机运行 `python scripts/install_formula.py` 创建独立 Python 环境并安装锁定依赖，模型放在 `models/formula/`。Dockerfile 也提供隔离环境，公式模型同样需要事先准备并随 `models` 只读挂载。包与模型原项目许可证均保存于本机模型目录，安装脚本固定官方发布资产及 SHA-256；运行期间不自动下载。

本机未安装 Docker，因此容器文件目前仅完成静态审查，尚无干净容器构建或启动通过记录。CPU 容器推理速度也未测量，不能等同于本机 Vulkan 表现。

2026-10-12 已在 `artifacts/reproduce-env` 新建独立 Windows 虚拟环境，按 `requirements-lock.txt` 从空环境安装成功，并用独立数据/账号库启动第二个真实 HTTP 实例。健康接口、15 页 PDF、前端和账号初始化均通过；检查结束后已停止该临时进程。命令为该环境的 `python -X utf8 scripts/check_reproduction.py`，报告在 `artifacts/full-workbench/reproduction/report.json`。此检查复用已有模型文件和推理服务，不等于新机器从零模型下载或 Docker 验收。

## 公开演示配置

公开实例必须使用 HTTPS，并设置 `SCHOLARTRACE_PUBLIC=1`；此时所有研究数据接口均要求登录，session cookie 为 HttpOnly、SameSite=Strict、Secure。`SCHOLARTRACE_REGISTRATION=0` 默认关闭公开注册。先在本机创建专用评审账号及演示文献库，再启动公开模式；切勿直接把本机默认空间匿名暴露。

公开隧道、评审账号交付、独立网络可用性检查和持续 24/72 小时运行验证尚需实际完成。这些配置文件不代表已经公网部署或稳定性验收通过。
