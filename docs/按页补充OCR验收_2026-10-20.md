# 按页补充 OCR：验收与使用说明

本轮完成暂停交接中的按页 OCR 草稿，主站入口为 http://127.0.0.1:8765/ 。源码与本轮证据独立交付到 `output/page-ocr-20261020/`，上一轮 `output/parsing-quality-20261020/` 不覆盖。最终采用与原数据保护以本轮 `release-selection.json` 为准。

## 解决的问题

一页 PDF 可能只有标题或图注可提取，正文仍是图片。只凭已有字符数无法发现这个缺口，原来的整篇自动 OCR 也不会处理该页。现在可以在“文献管理→详情→逐页文字覆盖检查”勾选“显示全部页面”，对目标页点击“补充识别本页”。

系统只识别所选页，保留原生文字块和标题。OCR 行只有在文字和页面位置同时匹配原生文字时才被跳过；其他位置出现相同文字不会仅因内容相同而删除。已有 OCR 引文不会被重跑覆盖。新增内容进入全文检索，语义索引随后在后台更新。

面板显示任务进度，结束后自动刷新，报告显示“原生 + OCR 补充”、重复行数和识别提示。混合页的 OCR 置信度优先统计新补充的文字，避免高置信度标题掩盖新增正文的低置信度。进度请求失败时明确说明后台任务可能仍在执行，可在任务与成果查看或手动刷新。

## 操作

1. 进入文献管理，点击论文“详情”，展开“显示全部页面”。
2. 如果原图中有正文而选中/检索不到，点击该页“补充识别本页”。等待面板更新；切勿把有文字页数当作完整识别证明。
3. 核对新增行数与跳过的重复行数，点击“查看原图”核验。也可以导出 JSON 记录。
4. 已有 OCR 的页显示“已有 OCR 引文，保留原结果”。暂不直接覆盖纠错，以免改变旧笔记来源。离开面板后任务继续，进度可在任务与成果中查看。

## 保留的失败与局限

首次真实 OCR 验收使用纯数字“73”作检索断言失败；检查原文块证明 OCR 实际已正确识别，原因是现有关键词提取不纳入纯数字。失败日志保留为 `first-attempt.log`，改用“hidden experiment samples”验证新正文检索后通过。本轮没有修复纯数字搜索，也不把该失败冒充识别错误或删除记录。

正文图片仍需要用户主动发现并指定页，字符阈值无法证明所有正文齐全。OCR 文本与位置去重属于保守规则，识别错字或位置偏移时可能保留重复。复杂多栏顺序、跨页表格和公式没有因此获得完整语义解析能力。旋转去重仅有受控几何测试，不代表任意旋转扫描件识别质量已验证。

实际 OCR 样例是集成验收，不是独立识别准确率基准。已有 OCR 内容的覆盖纠错及引文迁移、纯数字搜索、独立真人盲审、未见论文质量评估、最终 PDF/视频同步和官方提交仍待完成。
