## 3. 推荐作品：研证 · ScholarTrace（暂名）

以下是当前首选候选方案，不代表已经锁定选题。用户最新要求是以拿奖为最高优先，方向服从创新性、能力和质量。

一句话定位：帮助研究者把论文、论断、出处、版本和研究进展连在一起，并在证据变化后重新检查结论的科研助手。

### 3.0 先用小规模验证决定主攻方向

通用六模块是共同底座。主攻方向必须回答一个具体科研问题，并能给出相对普通方案的改进证据。暂时比较以下候选，不凭名称或界面决定：

| 候选主线 | 对评分的价值 | 最大难点 | 当前取舍 |
| --- | --- | --- | --- |
| 证据随版本更新的研究决策助手 | 同时关联抗幻觉、版本、图谱、科研交互，可展示已有结论的重新核验 | 识别哪些证据变化真正影响结论，防止误报 | 优先做小样，当前最看好 |
| 研究想法与后续进展核查助手 | 贴近前沿探索与选题价值，演示有明确问题 | 搜索覆盖不完整，很难证明“未被解决” | 作为第二候选和受限范围特色 |
| 论文复现准备与差异诊断助手 | 从参数、环境、代码线索走向可执行研究，实践价值强 | 仓库环境复杂，8 GB 显存和零费用限制完整复现 | 先检查是否能限定为可验证的小实验，暂不主打大规模复现 |
| 完全自主提出假设并完成研究的 AI 科学家 | 题目吸引力强 | 范围、算力、真实性和 38 天工期难同时控制 | 当前不作为优先方案 |

游戏 AI、强化学习等学科只在能显著增强真实场景和验证能力时再选，不能仅因个人兴趣牺牲官方用例兼容性。

前 2—3 天除环境可行性外，对前两个候选各做一条能运行的最小实验，并写明：对照方案、输入、真实输出、失败案例、耗时、资源占用和额外工程量。优先选择差异能被验证、六模块联动明显、零费用可稳定运行的方案。若核心收益不成立，应及时换主线，不为已有页面投入锁死方向。

质量门槛：证据不能造假；核心输出必须能被人工复核；主要功能可用且没有阻断流程的错误；界面清楚、演示稳定。功能数量、复杂架构名称和未经对照的“算法创新”都不作为替代指标。

核心流程：导入论文 → 解析并管理版本 → 阅读与翻译 → 提问并核对证据 → 追踪与建立引用图谱 → 比较研究进展 → 生成带真实引用的写作框架和图表。

初始界面设置三个工作区：

1. 文献库：论文导入、版本、解析进度、搜索推荐和订阅。
2. 阅读台：目录、PDF、双语阅读、问答与原文证据，点击结论即可定位高亮。
3. 研究台：引用图谱、跨论文比较、研究方向检查、写作及数据可视化。

### 3.1 特色一：可核验的证据链（最高优先级）

每个事实性回答关联具体论文版本、页码、原文块、坐标和原文片段。生成前先检索证据，生成后再校验引用存在且支持对应论断。回答区分原文事实、跨文综合判断、待验证假设。

不是只在答案末尾贴一个论文名称；评审应能点击“训练使用了什么 GPU”对应的出处，直接看到原文中的型号和数量。缺少证据时明确说明，不能补编。

工程数据结构先定义 `Document`、`DocumentVersion`、`Block`、`Claim`、`EvidenceLink` 和 `Artifact`，使问答、综述、版本管理及图注使用同一套来源记录。

### 3.2 特色二：版本感知的文献库（第二优先级）

用标识符、标题作者、正文相似性联合判断同一论文，文件哈希处理完全重复，语义比较处理不同版本。版本新旧使用可信的版本号/日期证据判断；不确定时提示人工选择。

官方重点流程为先上传 v7、再上传 v1。即使重命名文件，也应识别同一论文并建议保留较新版本，允许用户选择。高级功能按章节比较增删和实验变化；每条答案都保存使用的版本，避免 v1 的证据被默认为 v7。

旧版本仍可保留和切换。覆盖、保留、更换当前版本必须语义明确，删除后相应索引和引用状态要更新。

进一步候选创新是“证据变化影响分析”：当论文版本更新，沿已保存的“原文块→论断→回答/综述”关系识别受影响项，标记其新版适用性待复核，再仅对这些项重新检索验证。历史答案继续保留其原版本和原始证据，不因为新版本出现就被直接判错。格式变化不应触发事实错误告警，删除或改写也不自动等于推翻旧结论。

该机制先覆盖用户已经产生的结构化回答和综述，避免对全库无限抽取论断。以误报率、漏检率、重新检查的工作量和最终答案正确性对比“更新论文后沿用旧答案”的基线。真实论文版本为主要材料，自制变更仅用于标注为合成的压力测试。它属于待验证的工程创新候选，尚不能声称原创算法或已优于现有产品。

### 3.3 特色三：有证据的研究方向检查（第三优先级）

结合引用上下文和时间线提取 Future Work，再检索后续论文，判断是否存在直接支持“已解决”的证据。输出“已解决 / 部分解决 / 存在相关工作 / 暂未找到证据”等状态，并列明检索日期、范围和条件差异。

“没有搜到”不等于“全球无人研究”。不能把不同任务、数据集或假设下的成果直接当作该问题已被解决。

引用图谱采用入度、PageRank 等可解释基线，加上引用位置和用途分析。只声称在已收录的局域图谱中识别核心节点，不将局域排序包装成整个领域的权威排名。“引用含金量”给出用途、上下文和筛选理由，不直接删除原始引用关系。

| 模块 | 省赛前必须达到的表现 | 支持特色的实现 |

| 阅读与翻译 | 原生 PDF；目录导航；正文引文与 References 双向跳转；局部与全文翻译；双向同步滚动；公式代码保留 | 双语段落共用原文块 ID，通过段落/坐标同步而非仅按滚动百分比 |
| 检索追踪推荐 | 按论文名或引用找元数据与开放全文；增量追踪；个性化理由；GitHub 线索；点赞/踩 | 来源去重、可解释相关性、失败重试和多个用户偏好隔离；不把仓库存在等同于复现成功 |
| 图谱与综述 | 至少 20 篇引用关系图、核心节点、简短综述、Future Work 检查 | 区分真实引用边与相似性边；综述逐条出处；研究方向时间线 |
| 写作与图表 | Abstract/Introduction/Related Work 框架和真实 References；架构图脚本；CSV 图表及学术图注；中译英 | 结构化引用导出、来源数据和绘图脚本一起导出、统计结论校验 |

原文中的 TikZ/Graphviz/Mermaid/Matplotlib 为可选工具示例。先以 Mermaid 生成架构图、Matplotlib 生成学术数据图，保证至少一条可复现路径；再补 Graphviz/TikZ 导出。覆盖折线、柱状、表格和题面要求的三维雷达展示；多维雷达同时提供易读的二维视图和原始数据，避免展示效果扭曲比较。

### 5.2 候选技术栈

| 层级 | 初步选择 | 原因与取舍 |
| --- | --- | --- |
| 前端 | React + TypeScript + Vite、PDF.js、KaTeX、Cytoscape.js | 阅读器为核心的浏览器应用；前后端明确分离，减少不必要服务 |
| API 与任务 | Python + FastAPI，持久化任务队列/任务表 | 方便接入 PDF、OCR、图论和绘图；长任务与 HTTP 请求分离 |
| Agent | 明确状态的 LangGraph 工作流或等价状态机 | 规划→工具→检查→修正；限定重试次数、时间与上下文 |
| 存储 | SQLite 元数据/任务状态 + 本地文件；轻量向量索引 + BM25 | 起步资源小，允许以后替换持久层；备份覆盖文件和数据库 |
| 文档解析 | 原生 PDF 提取；OCR 专用路径；MinerU/PaddleOCR 类候选先做兼容性实测 | 保护原始坐标和阅读顺序；公式/表格不能假定普通 OCR 即可正确还原 |
| 生成模型 | Qwen 系列 4B 量化模型先测，再比较 7—8B 量化模型 | 8 GB 显存下必须结合上下文、KV 缓存和并发实测；不预先保证速度与质量 |
| 检索 | 轻量多语言 Embedding（如 multilingual-e5-small）、BM25、可选轻量重排 | 英文论文与中文问题互查；先测 CPU 成本，防止争抢显存 |
| 图谱与绘图 | NetworkX、Mermaid、Matplotlib | 算法可解释、图表可导出、脚本能重跑 |
| 外部数据 | arXiv、Crossref、OpenAlex/PubMed 等候选公开接口 | 逐一验证访问条件、配额、许可与稳定性；只获取合法可访问全文 |
| 运行与交付 | Windows 本地开发，尽早提供 Linux/Docker 配置和启动脚本 | 模型与数据外挂；不把机器上的缓存当成完整交付环境 |

最终选择由最初两三天的基准结果决定。固定依赖版本、记录模型许可证与来源，不照抄赛题列举的旧模型版本。

生成、OCR 和重排按资源预算调度，先串行处理显存重任务；长文档按页批处理，先生成结构和索引，不将 541 页全文塞进提示词。使用翻译缓存、解析缓存、检索缓存和部分 CPU 执行降低成本。

Agent 的界面展示真实的任务步骤、调用参数摘要、结果、耗时和错误恢复，不虚构隐藏思维过程。工具接收有类型的参数；文献内容作为数据，不允许其中的文字改变系统规则。生成绘图代码在有限权限、有限时间和指定目录内执行。

### 5.3 必须尽早验证的零费用约束

1. 模型效果：在固定的简短证据上完成细节问答、引用输出、工具参数生成和翻译，再决定本地模型档位。失败时先优化任务拆分、证据质量和重排，不能靠编造演示结果弥补。
2. GPU 兼容性：RTX 5060 Laptop 的推理和 OCR 环境必须做实际安装与运行检查，不能仅凭显存容量判定可用。
3. 公网：先试已有电脑运行服务，经免费通道提供外网访问；评估固定入口、重启恢复、带宽、跨网络访问和免费服务条款。免费托管平台只有实测后才纳入正式依赖。
4. 在线可用性：本地托管需要电脑开机联网并处理休眠。先做 24 小时、再做 72 小时可达性验证。具体评审结束时间未明确，不能只按提交当天安排服务。
5. 备用资源：若本机运行和免费公网服务无法同时达到要求，应及早确认可获得的学校/实验室已有资源或免收费额度。未落实前保留为风险，不能将免费额度当作长期承诺。

不依赖购买 API 额度，不订阅任何付费服务。官方测试集、模型权重与书籍的再分发权限分别处理；可以提供获取说明和校验值，不默认全部放入公开代码仓库。

## 7. 怎样证明效果：评测先于美化

先做约 30 条开发问题，再准备与调优分离的固定验收集，建议约 120 条并覆盖官方材料和不同排版的补充文献。数据未取得前不填写答案，不把自制替代集记作官方通过。

至少覆盖：单篇数值/单位/表格问答、多篇对比、无答案和冲突证据、扫描件、版本混淆、错误引用、查找文献、未来方向时间线，以及工具超时和中断恢复。

建议内部目标如下；它们不是赛事官方阈值，也不是当前成绩：

| 指标 | 建议目标或记录方法 |
| --- | --- |
| 引用可点击与定位 | 固定测试中的来源链接均指向存在的文献版本和正确原文块 |
| 事实答案正确率 | 已标注问题争取 ≥90%，按题型分别报告，不用平均数掩盖扫描件失败 |
| 论断获原文支持比例 | 争取 ≥95%，以人工核对为主；区分有链接和链接真正支持答案 |
| 无答案问题处理 | 争取 ≥95% 正确说明证据不足，并同时监控有答案问题的过度拒答 |
| 参考文献真实性 | 固定验收输出中不存在伪造条目；元数据无法核验时不得标成已核验引用 |
| 版本识别 | 官方指定 v1/v7 顺序及重命名测试通过，另测相关但不同论文的误合并 |
| 长文档鲁棒性 | 全本有逐页状态、失败重试和完整性检查；随机页抽检、靠后章节检索和恢复均验证 |
| 性能与费用 | 报告硬件、模型、上下文、首次/缓存耗时、峰值显存/内存、p50/p95、并发条件；外部付费调用为 0 |
| 公网可用性 | 不同网络可访问，重启恢复可用，24/72 小时试运行有日志；评审期另按通知保持可用 |

对照实验使用相同论文、模型与问题：普通向量检索 → 混合检索/重排 → 增加版本过滤与证据检查，比较准确率、支持率、拒答和延迟。图谱特色与单纯入度/PageRank 排序比较；研究方向检查与仅提取 Future Work 比较。结果不理想也如实记录，避免凭界面宣称创新有效。

挑选 3—5 位同学或研究者做小规模试用，记录同一任务的用时、错误数、成功率与体验；获取实际反馈后再写收益，不能预写“效率提升百分比”。
