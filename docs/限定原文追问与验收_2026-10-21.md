# 限定原文追问：使用方法与验收

本轮新增“只依据此段追问”，用于已经找到关键段落、希望继续解释其中机制或条件的场景。普通检索仍保留；选段模式只将用户选定的一段完整原文交给模型，不自动扩大到全文或其他论文。

## 怎么使用

1. 在文献阅读台选择论文，先提出问题，查看下方原文证据卡片。
2. 找到相关段落，点击“只依据此段追问”。系统重新读取当前完整段落，定位 PDF，并显示“只依据选中原文”及页码。
3. 展开“核对本次选中的完整原文”，确认范围后编辑问题，再按 Enter 或发送按钮。选段本身不会发送请求。
4. 建议一次问清具体关系，例如：“原文中，Post-LN 初始化时靠近输出层的参数梯度有什么特点？较大学习率会造成什么后果，warm-up 怎样帮助？”
5. 回答保留其选段范围。保存的有据回答及 Markdown 导出同时保留“只依据这一段”的说明；原文定位及回答核对清单仍可使用。
6. 点击“解除限定，恢复当前论文检索”回到普通问答；切换论文或检索范围会清除选段。选段时不显示后台问答入口，避免后台流程忽略该范围。

没有原文证据卡片时，先使用普通检索问答。当前仅支持一个完整原文块，长度为 12—4000 字符；超长段落提示重新选择，不静默截断。段落不包含的信息只能说本次依据不足，不能推断整篇论文未报告。

## 可信边界与实现

服务端核对论文、账户可见性、块归属、完整原文一致性和归档状态。过期原文或已归档论文拒绝请求，要求重新选择。保存范围记录含文献、页码、块标识和原文 SHA256。

生成继续经过既有引文、数字归属、语义条件及支持片段检查。为复用校验，将原来的生成后校验提取为共享函数；冻结检查确认该校验主体与上一交付 AST 一致。模型或解析失败时仅返回选中原文和失败提示，不退回全文检索。以上约束限制证据范围，并不保证模型一定正确理解原文。

## 实际验证

- 后端完整回归：420 项通过；新增 8 项覆盖无效/过期选段、归档、数字误述过滤、范围保存导出及生成失败不扩大检索。
- 前端 TypeScript 与生产构建通过。Vite 仍提示既有大包体积，尚未宣称性能全面优化。
- 真实 Chrome 完成 4 组流程：完整选段读取、真实限定问答和导出、解除限定、切换论文后的真实普通问答。手机 390px 无横向溢出，浏览器无页面异常。属于开发者自动走查，并非真人研究。
- 冻结 4 个开发案例、11 次本地模型调用，无调用错误。问题及段落由开发者从已暴露论文选定，不能用作独立准确率，也不能与自动检索直接作公平性能对比。

## 尚未解决及竞赛表达

复杂复合问题仍可能漏答；同一小模型的支持性审核可能漏掉推断越界；中文表达偶有重复或中英混杂。没有新增训练权重，没有证明零幻觉或真人效率提升。此次补强的是“找到原文—限制取证—聚焦追问—保存来源”的可检查流程。

演示可沿用八步真实论文指南，在阅读环节加入本功能。演示时同时展示有据机制回答和无依据显存问题，解释系统如何保留证据边界。公网部署、官方账号与最终提交状态、独立质量评测和最终 PDF/视频同步仍需分别完成，不能用本轮工程验收替代。
