# 后台问答与断点恢复验收

本轮解决复杂问答长期绑定前台 HTTP 等待的问题，增加可恢复的后台入口。没有替换或升级本地模型，也没有宣称答案准确率提升。

## 使用方法

1. 打开 <http://127.0.0.1:8765/>，在阅读台选择当前论文或明确选择 1—8 篇文献，填写完整问题。
2. 点击输入框下方“后台问答（可恢复）”。任务立即进入持久化队列，页面显示真实执行阶段和已保存篇数。进度按完成篇数估算，不是答案正确率。
3. 每篇论文完成后，可展开“已完成论文的结果”，核对引用或查看未解决项。后面的论文仍在运行时，前面的结果已保存在本机数据库。
4. 可以离开页面、切换模块或关闭浏览器。回来后点击“查看后台问答”，从当前账号的最近任务中选择原任务。无需依赖浏览器缓存。
5. 点击“停止后台任务”提出停止请求；当前模型调用可能仍需结束。任务停止后点击“恢复未完成论文”，已完成论文复用检查点，当前未完成篇重新处理。
6. 运行中的任务在网页服务重启后自动恢复。电脑关机时不会继续计算，重新运行启动器后才能恢复。
7. 完成后点击“打开完整回答与导出”，可下载 Markdown／JSON。任务也显示在“任务与成果”；从项目发起的后台问答最终自动收纳到原项目。

按 Enter 的直接问答行为保留，仍有 120 秒前台等待上限；长问题建议显式使用后台入口。后台入口不接受全库空范围，最多 8 篇，避免悄悄扩展取证范围。不是跨轮聊天记忆功能。

## 实现和状态边界

- 新增 `answer_checkpoints` 表，按任务 ID 与文献 ID 保存完整单篇结果，包括原始引用、逐项覆盖、未解决项和检索证据。与原任务、当前账号数据库关联。
- 后台任务仍调用现有 `research.grounded`，沿用原文存在、数字和模型支持性初筛。进度只展示实际执行到的阶段；一篇没有通过核验的答案也属于已处理，不等于答案完整。
- 一篇完成后保存检查点。中断或失败后的恢复只处理未保存的论文；当前篇内部的子问题暂未逐条保存，当前篇仍需重新运行。已保存的未解决项不会因恢复自动再生成，需要新提问处理。
- 最终汇总保留各篇独立章节、原始文件名、来源和发起项目，保存为普通问答成果。停止时的检查点通过阅读台查看，不提前伪装成完整成果。
- 如果进程在最终成果已保存、任务状态尚未更新时中断，恢复时通过原任务标识复用已保存成果，避免重复保存。该崩溃窗口由专项测试模拟验证。
- 新提交校验问题、1—8 篇范围、归档状态和项目成员；相同参数的运行中任务复用既有任务。已提交任务按原文献列表继续执行，之后修改项目成员不会改写该任务输入。
- 复用现有任务队列的并发、取消、异常和重启恢复机制。网页轮询失败会保留已有结果并继续重试；任务仍在服务器执行。
- 首次项目深链接中，详情可能早于全局文献库返回。已修复此时启动按钮可点击却无动作的竞态，等待关联文献可用后再启用入口。

## 真实验收

输入为项目中的 Attention v7／v1 两篇论文，问题是 GPU 设备与 seed 42 单次 BLEU。实际使用现有本地模型和真实数据库，没有用模拟回答代替浏览器验证。

| 操作 | 实际结果 |
| --- | --- |
| 后台提交 | 本次浏览器测得约 464 毫秒返回任务；这不是模型回答耗时或性能保证 |
| 第一篇完成后停止 | 第一篇完整检查点保留，第二篇未完成；部分结果可查看 |
| 刷新浏览器 | 从服务端任务列表找回原任务和第一篇结果，不依赖 localStorage |
| 恢复 | 第一篇复用原结果，开始处理第二篇 |
| 第二篇运行时重启网页服务 | 只重启经过进程身份核对的本项目网页服务，本地模型保持运行；守护程序恢复服务，任务自动继续 |
| 比较恢复前后 | 第一篇检查点完整 JSON 一致；事件日志有 3 次任务启动，覆盖初次、手动恢复、重启恢复 |
| 最终结果 | 两篇各有 P100 回答，单次 BLEU 保持未解决；结果保存为一份成果，原项目包含任务和成果关联 |
| 打开与导出 | 阅读台可打开完整回答，显示每篇逐项状态，可下载实际 Markdown |
| 手机 | 390 px 视口无整页横向溢出，已查看桌面部分状态和手机完成状态截图，无 JavaScript 页面异常 |

首轮浏览器检查因上述项目入口加载竞态失败，失败日志保留；修复后完整流程通过。部分结果截图抓到 UI 下一次轮询前的“正在停止”文字，服务端已经确认 cancelled；停止及最终状态以保存的请求与结果断言为依据。

- 前端 TypeScript 检查与正式构建通过；新增 Python 模块和测试 Ruff 通过，diff 空白检查通过。仍有既有 Mermaid 分包体积提示。
- 40 条文献、47,872 个原文块和 2 条笔记前后摘要一致，270 份既有成果内容保持不变，仅新增 1 份最终后台问答成果。SQLite 完整性检查为 ok，网页与模型健康正常。

## 当前限制

- 检查点以论文为单位，不支持模型 token 或单个子问题级别续算。
- 最近任务选择器复用当前账号最近 100 个总任务的列表；更早的完整成果可在“任务与成果”查找，尚未提供无限分页的后台问答历史。
- 队列没有给出可靠剩余时间估计；停止要等到可取消的处理边界，当前模型调用可能仍消耗时间。
- 本地服务未运行时无法查看结果。没有公网部署或多机任务分发。
- 本轮没有解决 FlashAttention 等复杂问题的所有漏答、无幻觉保证或独立准确率评估。
