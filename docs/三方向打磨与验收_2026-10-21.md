# 三方向打磨：回答核对、比较边界、真实论文演示

本轮将三条改进方向落实为可操作入口，并修复了真实走查中发现的单篇补问范围问题。目标是提高研究过程的可检查性，不宣称已经解决模型的复杂推理与全部漏答。

## 1. 回答核对清单

新回答会根据原问题里的明确词语，列出机制、实验条件、限制、epoch、学习率、batch、参数冻结与更新、数据、数值单位等要求。各项可以展开相关回答、跳转原文，或点击“补问”将原问题、该项要求及原文献范围带回输入框；不会自动发送。

清单随新问答成果保存，阅读台、后台逐篇结果、任务成果及 Markdown 导出均可展示。旧成果没有这个字段时不伪造历史清单。

“有相关表述”只说明词语定位到了候选句，不代表该要求已经答全、解释正确或来源支持完整。“未定位到对应表述”也不是论文未报告的证明。当前不支持任意隐含意图的完整语义识别，已有机制漏答依然需要继续攻克。

真实走查发现：原先补问一律切换为多篇选择，即便只有一篇；之后切换阅读论文可能继续查询上一篇。已修复为单篇补问使用当前论文范围，多篇补问仍保留原多篇范围。浏览器实际验证第二篇的结果来自第二篇，未通过放宽来源断言绕过问题。

## 2. 比较前检查

在证据笔记的边界对照表中，新增待补格清单、原文摘录单位线索和实验阶段线索。单位或阶段线索不同会提示继续核对定义、量纲、换算与训练／推理条件；没有识别到的线索明确显示未识别，不当作一致。

检查只读取已保存格子中的原文摘录，不把用户整理中自行写入的数字当作原文测量。毫秒与秒分别识别；GB、tokens、样本、百分比等只是有限线索。系统不自动换算，不自动推断数据集相同，不判断两篇论文可比或哪篇胜出。

点击“补齐研究对象／实验条件”等按钮可直接进入对应单元格编辑，沿用原有同篇来源与摘录核验。仍缺证据时，从原空格加入补查待办，保留未解决状态。检查随对照详情、Markdown/JSON、项目 ZIP 导出，状态由当前快照计算，避免保存旧评分。

## 3. 比赛演示主线

选用两篇真实论文：Layer Normalization（1607.06450v1.pdf）和 On Layer Normalization in the Transformer Architecture（2002.04745v2.pdf）。主线为“问题→清单→原文→笔记→对照→补查→导出”，同时展示一个真实失败反例与当前边界。

交付包含八步交互指南和逐步讲稿，建议排练安排5—7分钟；不是实测人工效率。讲稿不会自动创建数据或编造训练结果。对照仍保留8个待补格，如实表明当前证据尚不足以完成全部比较。

详见 [真实论文演示讲稿](真实论文演示讲稿_2026-10-21.md)。HTML指南位于 `output/research-polish-20261021/演示指南.html`。
