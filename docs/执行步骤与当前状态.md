## 第三步：第一条研究流程（已实现并验证）

做什么：真实论文 → 原文检索 → 本地模型回答 → 点击出处高亮 → 保存笔记 → 跨版本复核。

怎么做：输入和输出都引用固定文献版本及原文块。模型引用必须对应存在的原文；错误/缺少依据时保留原文检索结果，不伪造生成成功。版本比较先做文本对齐，再由本地模型围绕笔记判断含义变化，两侧引文均检查存在性。

实际示例：Transformer v1 的结论中承诺近期公开代码，v7 的结论中已经提供仓库地址。另一个硬件训练段落只有表述变化，模型初判关注的硬件信息未变。两例均来自真实 PDF，不是改写的演示文件。模型判断不是科学真伪证明，原文始终可以人工核对。

### 你现在可以直接操作

1. 打开 `http://127.0.0.1:8765`。如果服务没有运行，双击根目录 `启动研证.cmd`。结束使用时可双击 `停止研证.cmd`。
2. 在左侧选择《Attention Is All You Need》的 v1，文件栏应显示 `1706.03762v1.pdf`。扫描版会标“扫描件”。
3. 输入“Base 模型训练用了多少个 GPU？具体是什么型号？”，等待本地回答。
4. 点击回答下的原文卡片或“核对原文”，查看 PDF 对应页的黄色高亮。也可以问 Adam 参数。
5. 点击“存为笔记”，写下这条证据支持的观察，然后保存。
6. 打开“版本复核”，选择同一论文的 v7，点击“检查证据变化”。页面会保留旧/新原文，展示文本变化及本地模型初判。
7. 直接查看已准备的两条“验收样例/版本复核样例”笔记，可体验真实硬件段落和代码公开状态的变化。
8. 可再问“每张 NVIDIA P100 GPU 的采购价格是多少美元？”，核查系统是否说明当前证据不足。

阅读台手机尺寸下提供文献选择器；当前以桌面科研阅读为主要设计场景。
