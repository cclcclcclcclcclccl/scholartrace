# 答辩与 AI 协作说明

参赛者：蔡晨霖，西安交通大学人工智能2501。个人作品，未编造导师、团队成员或独立用户研究。

一分钟介绍：墨衡是面向论文阅读、比较和更新复核的全流程科研助手。它覆盖六个赛项模块，以证据生命周期为主线：回答回到原版 PDF，笔记绑定证据，论文更新后追踪已有结论与成果是否需要复核。近期补强回答核对清单、比较前检查和限定原文追问，把漏答和条件缺失变成可执行的补查流程。使用免费本地模型，保留真实失败和不确定性；420 项工程测试不等于科研准确率。

## 必须能够解释的技术问题

- Agent：结构化任务计划、允许的工具、参数校验、任务持久化和恢复；不是任意执行模型生成的系统命令，也未声称已实现自主科研发现。
- RAG：BM25 与多语言向量检索融合，文献/版本范围过滤，按问题组织证据，再生成与核验。引用存在不等于论断成立。
- 模型选型：Qwen3-4B 量化模型满足零 API 预算和本机资源约束。不是强云模型等价替代，未做基础模型训练。
- 创新：证据到笔记和成果的依赖、版本变化影响复核、条件敏感的补查流程。属于可检查的系统与交互创新，不虚称原创基础算法。
- 选段追问：只发送一段当前完整原文，拒绝过期选段；失败不扩大检索。不能把“此段未说明”写成“全文未报告”。
- 质量：已见开发题会受到迭代影响；4 个选段案例不能代表独立准确率。原复杂题仍漏答，同模型审核可能共享偏差。
- 费用：未购买域名、服务器、API 或付费订阅。免费公网方案依赖本机持续运行，静态入口不等于在线 AI 服务。

## AI 协作披露

AI 编程助手参与需求梳理、代码实现、测试、评测分析、文档、录屏和部署整理。作者提出目标、方向及交互修改意见，须亲自理解、核验并负责最终提交。保留真实已有 Git 历史，整理时提交当前代码，不回填伪造的日期或细碎开发记录。
