# 版本复核一致性与关注点防护验收

日期：2026-10-14。入口：http://127.0.0.1:8765/ → 版本复核。

## 本轮改进

- 模型判为“未见变化”时，额外检查实际比较引文：同一句式中的数值不同、明确否定词差异会把判断降为“不确定”，保留模型原判断和两侧引文；规则不会擅自改成“确认变化”。
- 数字使用 Decimal 规范化：0.001 与 1e-3、1,000 与 1000 不因表示方式不同被误拦截。只检查模型选择的比较引文，不把未选中的无关数字强塞进当前判断。
- 模型判为“变化”时，对笔记中明确出现的 GPU、批大小、学习率、层数、BLEU、参数量进行有限关注点检查。指标未出现在两侧引文，或该指标对应句子在完整比较段落中一致时，暂缓变化结论。未知概念不强行推断。
- 笔记复核与成果影响分析都显示“本次实际比较的引文”，不确定项默认展开。完整上下文及原文定位仍保留。
- 模型失败／无法核验、没有语义结果，以及超出每次 12 条处理上限的笔记都有明确提示。页面汇总初判未变、初判变化、不确定和未取得判断的数量；不将这些数量称为准确率。
- 全局帮助已同步，用户可点击版本复核标题旁的“怎么用”。

## 真实模型检查与未解决项

以下是小规模开发检查，不是独立盲测；用来发现缺陷并验证修正，不能据此报告总体准确率。

| 样例 | 来源性质 | 实际结果 |
|---|---|---|
| batch size 64 → 128 | 人工受控扰动 | 本地模型判为变化 |
| does converge → does not converge | 人工受控扰动 | 本地模型判为变化 |
| rate 0.001 → 1e-3 | 人工受控扰动 | 本地模型判为未变 |
| GPU 都是 8，仅分数 25 → 30，笔记只关注 GPU | 人工受控扰动 | 修正前误报变化；修正后转为不确定，明确提示关注点不匹配。尚未自动给出正确的“未变”结论 |
| Attention v1/v7 代码发布声明 | 真实论文及现有证据笔记 | 文字规则识别“计划发布 → 提供代码地址”；不代表仓库当前可用或实验复现成功 |
| Attention v1/v7 GPU 笔记 | 真实论文及现有证据笔记 | 本地模型引了相同句子却判断变化，既有防护转为不确定；仍需人工查看上下文，此项没有解决为自动正确判断 |

另构造“模型错误地把 8 GPUs → 16 GPUs 判为 same_claim”的固定响应，验证新增一致性检查会输出 unclear 并保存警示。这是受控错误响应检查，不是声称真实模型在该输入上必然犯同样错误。

## 验收结果

- 后端完整测试：224 passed in 37.42s，比此前新增 14 个用例；版本复核相关文件共 29 个测试通过。
- TypeScript 与 Vite 构建通过；既有大包警告仍在。新增防护模块静态检查通过；不宣称全仓库存量 lint 问题清零。
- Chrome 实际请求版本复核接口，检查真实 v1/v7 返回、状态汇总、比较引文和旧版出处跳转。
- 浏览器对受控错误响应做显示回放，验证“不确定”标签、数值警示和引文展开。这一部分只是 UI 验证，未将合成句子存入用户笔记，也没有冒充真实论文内容。
- 390px 视口无全页横向溢出；无 JavaScript 错误。
- 原有 40 篇文献、47,872 个原文块、2 条笔记和 271 个成果逐行哈希一致，数据库 integrity_check=ok；网页与本地模型健康。

## 边界与下一步

本次主要降低错误确定性，可能增加需人工复核的条目。数值防护只覆盖句式一致的差异，不理解所有单位换算、公式和实验条件。关注点检查只覆盖明确列出的少量指标，并不证明引文相关性或全文蕴含关系。引文编号若未匹配参考文献，也可能触发谨慎提示。

仍需建立独立标注集，分别测量对齐成功率、变更漏检率、误报率、不确定比例和人工复核时间；真实版本样例与合成扰动必须分开统计。此次不能声称已提高到某个准确率，也不能声称达到获奖验收标准。
