# 新题对照、证据修复与开发者走查

本轮目标：在真实用户无法参与的条件下，用可复现的开发者任务检验核心能力；不把开发者操作当作真人反馈，不继续用功能数量证明作品质量。

## 实际结论

研证具备可运行的证据工作流，但还不能声称问答全面领先。七道小样本任务中，当前研证与普通检索问答均为4道完整通过或正确拒答；研证另外3道为有据但遗漏，普通检索另外3道出现实质错误。零原文输入的同一本地模型仅1道正确拒答，其余6道有实质错误。不能据此估计所有科研问题上的准确率。

| 范围 | 模型直接回答 | 普通检索问答 | 研证完整流程 |
| --- | --- | --- | --- |
| 4道开发诊断题，完整通过 | 0/4 | 1/4 | 修复前1/4，修复后2/4 |
| 3道保留确认题，完整通过或正确拒答 | 1/3 | 3/3 | 2/3 |
| 合计7题，完整通过或正确拒答 | 1/7 | 4/7 | 4/7 |
| 合计模型调用次数 | 7 | 7 | 66 |
| 单题端到端中位耗时 | 1.875秒 | 3.328秒 | 18.782秒 |

上述耗时为同一台共享开发电脑上的单次运行，包括检索与等待，未重复计时、未测统计显著性；研证有更多调用和处理步骤，不是等计算预算比较。跨论文题普通检索回答更完整，这一反例必须保留。

## 怎样查看结果

- 可筛选报告：`artifacts/transfer-comparison-20261020/report.html`，浏览器打开即可。支持方法、结果筛选和关键字搜索，展开查看完整原始答案、冻结标准及PDF页码/原文块。
- 原题及标准：`evaluation/transfer_comparison_20261020/protocol.json`。
- 逐题开发者复核：同目录 `review.json`。评分者是同一开发助手，不是独立评委；关键词和引用存在检查不替代语义复核。
- 原始推理：`artifacts/transfer-comparison-20261020/` 下 `diagnostic-first/`、`diagnostic-candidate1/`、`confirmation-first/`，分别保存 `run.json`、`model-calls.json` 和运行前后数据库校验。
- 诊断题重测只运行产品，不把重复结果当成新样本；确认题在候选代码指纹固定后首次运行。

选择 Layer Normalization、On Layer Normalization in the Transformer、RWKV 和 LLaVA。经扫描既有题库，这七道问题未见先前问答记录；四篇论文早已在文库，LayerNorm也在引用检索测试中出现过，不能称完全未接触论文。模型预训练是否见过它们未知。

不可答题询问单张RTX4090上LLaVA Stage 2训练的精确显存实测值。全文已解析文本没有4090命中，相关训练段落报告8×A100。本项检验不编造指定实测值；不是对所有PDF图像的穷尽缺失证明。

## 本轮实际修复

1. **格式要求不再变成独立科研问题。** “请分别回答”“逐项作答”等跟随原问题保留，避免额外检索、重复回答和无关性能断言。包含具体内容的新问题仍保留独立覆盖项。
2. **阶段标题与原句一起核验。** LLaVA Stage 1的正确候选曾因选中的支持句不含阶段数字而被误拒。现在仅对同一原文块内明确的Stage/Phase/Step开头标题保留连续上下文，不跨越其他阶段、不借用别篇原文；错误的阶段编号和凭空增加的数值仍拒绝。
3. **选段为空不再直接等于无答案。** 对合法空选段，从已有字符预算内的候选上下文做一次有上限的抽取，随后仍执行原有引文、数值、支持性检查。无效引用编号仍拒绝。此改动补回部分解释，但没有解决全部覆盖问题。

没有训练模型权重，也没有换成付费GPT。实际运行的是本机Qwen3-4B Q4_K_M，8192上下文、温度0；模型文件哈希与运行属性保存在报告中。

## 真实论文使用走查

仅预置一个包含两篇真实论文的项目，文库和账户库均为隔离副本；笔记、对照和补查回填经真实浏览器操作完成，未将虚构实验数值作为源材料。

1. 进入阅读台，选择Layer Normalization；页码框清空后输入7、6、9并按回车，确认实际页码变化。
2. 在研究问题中输入 `Layer normalization batch size 1 pure online regime`，按回车发送；从返回的原文中定位PDF第2页。
3. 选择“存为笔记”，写下自己的观察并“保存证据”。观察应区分原文结论与自己的推广，不能因batch size 1可用就推断任意任务必然更准。
4. 对Pre-LN论文提问 `Post-LN Pre-LN expected gradients at initialization warm-up`，核对第1页原文，再保存另一条笔记。
5. 进入“证据笔记”→“开始边界对照”，勾选两篇笔记创建表格；选择包含这两篇论文的项目。
6. 从空白“实验条件”格加入研究待办，开始补查，选择本篇笔记，填写研究整理与实际原文摘录，点击“保存依据并回填”。
7. 返回对照表核对结果；项目JSON/ZIP导出保留待办历史、来源和回填内容。

浏览器走查35个具名动作/等待步骤，26.977秒完成，无页面脚本异常；桌面及390px手机宽度检查通过。这是脚本执行时间，**不是用户完成时间，更不能换算为节省了多少人工时间**。导出内容有断言核对，截图与日志见 `artifacts/transfer-comparison-20261020/workflow/`。

该走查覆盖真实论文的阅读→证据→对照→补查→导出，不包括真实新旧版本变更或真人理解程度；既有版本复核测试仍是其各自的历史证据。

## 工程验收与尚存问题

392项后端测试通过（本轮新增7项）。本轮变更文件静态检查通过。全后端宽泛静态扫描发现46条既有规范问题，未宣称全仓库静态检查通过；主要为旧导入顺序、正则别名等。本轮未改变前端源码，无需重新生成前端构建产物。

27道既有问答重新运行，224次模型调用无运行错误。22道可答题中21道通过原有中文关键词筛查，ZeRO一题用正确英文术语回答，因此机械检查仍为失败；5道不可答题保留拒答。完整回答已与原标准复核，原关键词规则与失败标志没有修改；机器筛查和开发者语义判断分开记录。各题仍有重复、译法和解释细度问题，不能宣称所有措辞完美。所有候选论断的来源存在检查按原规则保留。

正式网站已受控重载，健康检查与桌面/手机只读检查通过；模型进程保持不变。整个研究文库29张非FTS表的内容哈希与本轮开始前相同。隔离走查服务已关闭，正式站点仍为 `http://127.0.0.1:8765/`。

仍需改善的实际问题：

- Pre-LN问题仍漏掉Post-LN初始化大梯度的完整解释；“良好行为”译法不自然。
- RWKV回答有重复，并未把矩阵乘法与WKV serial scan的差异讲全。
- 跨论文对照有正确来源仍可能漏掉均值/方差、结构位置等字段。不能把“有引用”当作“回答完整”。
- ZeRO旧题回答使用了英文术语，中文关键词机械检查未通过；需分别保留机械失败与语义复核，不能篡改旧标准让检查变绿。
- 4B本地模型存在基础知识混淆。证据核验增加了等待时间，也会误拒正确内容；没有证明模型能力已足够解决所有论文。
- 真实用户理解度、满意度、操作负担尚未验证，开发者走查无法替代这些结果。
- 七题为同一开发者设计和评分的小样本，四题参与调试；正式外部评测、比赛官网最新要求、报名及官方提交状态没有在本轮核实。旧技术PDF/视频仍对应旧快照。

后续优先级是补足字段级覆盖、减少重复与等待，再扩大来源明确的保留题规模；不以继续增加页面模块代替这些改进。

## 复现边界

使用 `.venv/Scripts/python.exe scripts/transfer_study.py run --split diagnostic --label 新目录名 --product-only` 可重跑已暴露诊断题。该命令复制正式文库，写入独立目录；禁止覆盖已有运行记录。确认集已经运行过，再跑只能称重复验证，不能重新称未见测试。

准备阶段发生过二进制向量无法JSON序列化的快照错误，在任何答案推理前修正为二进制内容哈希；冻结题目与标准没有改动。第一次评测协议内的runner指纹与后续运行指纹不同，运行记录保存了各自实际脚本指纹，不能将它们混为同一脚本版本。
