# 表格、证据问答与版本复核质量改进

日期：2026-10-12。项目：研证 · ScholarTrace。预算仍为 0 元，实际推理继续使用本机 Qwen3-4B Q4_K_M；没有付费 API 回退。本轮补充实现和失败驱动的开发回归，不能据此宣布全部赛项验收完成。

## 用户现在可以怎样使用

1. 启动 `启动研证.cmd`，访问 `http://127.0.0.1:8765/`。
2. 在“文献管理”选择论文，可编辑标题和常用别名。例如 GPT-1 的论文正式标题不含 GPT-1，可添加这个简称帮助跨文问题定位。别名属于用户元数据，不作为论文事实的证据。
3. 打开“表格提取与校对”，输入页码，选择自动候选或拖动框选，再点击提取。原生 PDF 使用实际词坐标，扫描件使用本地 OCR；完成后原图和可编辑单元格并列显示。
4. 点击单元格核对原图位置。可编辑内容、增删行列、调整分列线；保存后可下载 CSV，以及包含原始坐标、初次识别和修改历史的 JSON。也可在“任务与成果”重新打开。
5. 在阅读台选择多篇论文提问，每篇分别检索、作答和核对。数值行的回答会提供“核对表头”入口。缺少可核验依据的篇目单独显示状态。
6. 在版本复核中查看新旧证据。跨页引用提供各段原文按钮；衔接时跳过的图表和页脚也可展开核对。明确文字规则的结果与模型初判分开标示，历史笔记和成果保留。

## 表格提取与人工校正

原先普通文本抽取容易把空白列移走、将多列数字连成一串。本轮根据原始文字框位置恢复行列，保留空白；跨列内容显示 `[跨列 …]`，不把共享训练成本误归到单个语种。

提取过程保存原始截图、文字框、OCR 置信值、单元格坐标、列分界和首次矩阵。修改使用版本号检查，另一页面保存过时返回 409，避免静默覆盖。只改文字保留原始定位；增删行列后移除不再可靠的坐标映射。重新分列保留先前人工编辑历史。CSV 保留中文和负数，并避免将论文中的文字当成电子表格公式。

实际检查的是 Transformer v1 三张表的原生和扫描形式，共 6 个样本，包括 BLEU/训练成本、超参数表和解析 F1 表。指定数值、空白及合并内容检查 6/6 通过。扫描解析表提取为 12 行 × 3 列，其中 Transformer 两个 F1 数字 91.3、92.7 与原图一致。

这不是所有单元格或所有表格的准确率。扫描识别仍会漏掉参考文献方括号，科学计数法的上标可能变成同行数字；多层表头和不规则版式仍需原图核对。没有把 OCR 置信值当作表格正确率。

证据：`artifacts/quality-round2/tables-first-run.json`、`table-geometry-regression.json`、`table-ui-report.json`、`table-desktop.png`、`table-mobile.png`。浏览器实测涵盖提取、原图高亮、编辑保存、真实导出、成果重开、重新分列历史和 390 px 布局。

## 问答：修复错误归属和数字幻觉

本轮发现并修复了以下实际错误：

- GPT-3 架构表行单独进入模型时，隐藏维度、单头维度和头数发生混淆。现在关联同页几何位置匹配的真实表头，保留两个来源锚点；表头也被记录为版本依赖。
- 跨文问题把一篇的规格归到另一篇，或把“另一篇缺资料”并入有效回答。现在逐篇处理，拆出本篇问题，分别展示引用与覆盖状态。
- 一篇论文内同时询问多个规格时，规划曾只保留 BASE。现在单篇问题不缩减原问题，并要求保留所有被问到的规格与字段。
- 短小的 Context 标签排在实际窗口长度段落前。检索增加多个具体字段的查询、词覆盖排序和候选重排，相邻定义段以独立引用补入。
- BERT 数值回答曾包含引用原文没有的 128、256，模型自查仍予以通过。因此增加确定性的数字存在检查，支持显式科学计数法、千分位、百分数、百万／亿等单位换算，区分模型简称中的编号与测量值；不存在于所引证据的数字被剔除。

数字存在检查只是一项必要条件，不证明数字属于正确模型、正确列或适用条件正确；这些仍依赖表头、来源范围、模型初筛及读者复核。当前规则也不负责任意数学推导或所有中文数字表达。支持性检查使用同一个本地模型，不能视为独立事实裁判。

对最终原始文本的复查还发现：个别回答重复同一事实，或附带未直接询问的单头维度；GPT-1 的训练序列 512 tokens 还被补充表述成“上下文窗口 512”。后者超出了该句直接说明的训练条件，机械检查没有检测这种表述扩展。这些仍是需要继续解决的回答边界问题，因此 8/8 机械检查不能替代逐项语义验收。

开发问题集 v2 在第一次调用前写定并标注来源，首轮仅 3/8 通过机械检查，错误输出完整保留。经过多轮修复后又发现 v1 的 BERT 规格回归和中文简称触发误拒答，均保留了失败与修复记录。最终结果见下方汇总和原始 JSON。所有用于修改的题目均属于已暴露的开发题，不能称为独立泛化准确率。

复现此轮元数据：在文献管理为 `language_understanding_paper.pdf` 添加 `GPT-1, GPT1`；为 `2005.14165v4.pdf` 添加 `GPT-3, GPT3`；为 `N19-1423.pdf` 添加 `BERT`。评测报告记录了别名、题集哈希、后端源码哈希、每题原始回答、出处与耗时。别名没有包含任何预设答案数值。

## 版本复核：保留变化和原始上下文

原来只对比单块的方式容易把拆段、合段、跨页续句判断成变化。现在同时匹配连续的 1—4 个原文块，保留全部原始锚点。跨页续段仅在识别到少量图表、标题或页脚时尝试衔接，并暴露被跳过的内容；不跳过普通变更段落。数字边界严格匹配，100 不等于 1000，微小数字修改不因相似度接近 1 而视作原文保留。

语义复核由模型选择原文句子的编号，服务器复制对应句子，避免模型改写证据。两侧所选句子完全相同时，不允许用它们宣称“发生变化”。引用编号变动只有在实际文末条目匹配后才被视为编号变化，数学方括号不会被直接忽略。明确“计划发布代码”到“代码已可获取并给出地址”的变化增加保守规则；否定、条件或仅发布文档不会按此规则判断。

12 个真实版本案例包括 Transformer v1→v7，以及同一涌现能力论文的两种 PDF。标签由开发代理读取原文后标注，不是独立人员评审。此前单块对齐提示 7 个候选，新对齐提示 6 个；跨页解析段不再因分页而误报。这个数值仅是选定案例中的候选量，不是用户节省时间的测量。

一个有价值的实际冲突被保留：Transformer v7 摘要／表格的法语 BLEU 为 41.8，而对应正文仍写 41.0。系统按所引用的位置分别比较，不擅自把全文所有 41.0 改成 41.8。
