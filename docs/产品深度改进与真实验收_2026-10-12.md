# 产品深度改进与真实验收

日期：2026-10-12。项目：研证 ScholarTrace。预算：0 元。该报告回应用户关于科研痛点、差异化、解析、模型、幻觉、翻译、发现、研究辅助与写作绘图的质疑。功能可运行不等于科研正确率达标，不等于全部赛事验收完成。

## 产品要解决的问题

研究者的实际困难不是只有“读不懂英文”：相关论文难找和难筛；不同论文的数据集、指标、划分不一致，数字不能直接比；重要设置散落正文、表格、附录与代码；阅读结论和原始出处容易失去联系；原论文修订后旧笔记、综述可能过时；研究设想缺少可检验假设、对照实验和失败标准；科学绘图容易出现轴、单位、归一化或数据来源误用。

产品主线：找论文 → 管理与阅读 → 提取逐项证据 → 比较研究条件 → 制定待验证实验 → 写作与绘图 → 版本更新后复核受影响成果。突出“证据随科研过程可追查”，避免把普通聊天窗口当成主要创新。版本依赖和矩阵结合是当前工程特色，尚不能宣称学术首创或优于所有竞品。

## 本轮落地能力

| 用户入口 | 本轮增加或加强 | 使用与边界 |
| --- | --- | --- |
| 文献阅读台 | 全文段落搜索、结果分页、页书签 | 搜索已解析原文，点击回到页与坐标；扫描未识别文字无法搜索。书签持久保存。 |
| 文献管理 | 项目分类、标签、待读/阅读中/已读/待复现 | 保留原文元数据；可筛选阅读清单。API 同时支持标签与分类过滤。 |
| 双语与引文 | 术语表、译文人工校正、历史、过期写入冲突检查 | 术语优先用于新翻译；已有译文不静默覆盖。代码、公式、URL 先保护，避免术语替换破坏它们。 |
| 翻译质量 | 数字保留与额外数字检查；否定和不确定语气风险提示 | 后两项是启发式，不是语义准确率证明。人工校正保留旧译文。 |
| 科研工作室 | 1—6 篇 × 1—6 问题的证据矩阵 | 每格独立检索核验，保留引文、页码与表头。缺证据或核验失败分开显示，缺项进入复现前待补清单。 |
| 成果版本复核 | 证据矩阵也进入版本依赖分析 | 同一格在矩阵和章节导出中的重复表示只核验一次。原始成果不改写。人工草稿尚无逐句依赖，不假称自动核验。 |
| 任务与成果 | 写作/综述/矩阵可编辑草稿、保存历史、Markdown 导出 | 保留原始生成内容与证据；编辑稿明确标“尚未逐句核验”。多页面旧版本写入返回 409。 |
| 研究方案 | 用核验过的相关工作构造引言；结构化实验计划 | 要求假设、基线消融、数据划分、指标判定、资源可行性、失败条件；未开展实验不写成已取得结果。 |
| 绘图 | 自然语言转可编辑参数、散点图、对数轴 | 模型只选择 CSV 中存在的列，不生成数据；用户核对轴/单位/刻度后绘图。非正数不能使用对数轴。 |
| 论文发现 | 年份筛选、最新排序、翻页、账号内短期查询缓存 | arXiv 年份按首次提交时间，Crossref 按发表时间；外部失败时仅使用同查询历史缓存，并明确显示非最新。主题追踪始终实时请求，不使用查询缓存推进游标。 |
| 问答 | 重排后恢复相邻定义/规格段落；近似重复过滤；训练长度语义边界 | 训练序列长度不等于最大上下文窗口。数字存在、引文存在、模型初判都不能替代完整语义复核。 |

## 文献与模型的当前事实

本地文献由原始 39 份增至 40 份，共 2,010 页；47,872 个文本块已有向量索引，原有 2 条笔记保留。新增 GPT-2 原论文来自 OpenAI 官方 PDF，来源及 SHA-256 见 `data/competition/supplemental/provenance.json`，在“公开补充文献（非赛事原始集）”分类内。新增数量不代表扩大到一个完整学术数据库。

模型仍是本机 Qwen3-4B Q4_K_M，llama.cpp，8192 上下文。适合零成本离线基础任务，但在复杂条件理解、多个模型变体覆盖和高质量学术写作上仍不足。应把模型选择建立在同题、同证据、相同评分标准的比较上，覆盖正确性、拒答、遗漏、延迟与资源，而不是只按参数量或品牌判断。

本轮没有接入或调用收费 GPT。当前预算为 0，未提供官方 API 凭据；不能承诺强 GPT 免费可用。更强模型可以改善复杂理解和表达，但不能修复错误解析、漏检证据、没有定义的实验问题，也不能承诺零幻觉。后续可先比较本机能运行的更大开放模型；若用户之后提供合法可用的模型额度，再在同一评测框架下加入云模型。模型能力升级仍是待完成的质量工作。

## 借鉴了什么

2026-10-12 已取得以下官方产品页，原始文本和请求状态保存在 `artifacts/product-audit/`：

- Elicit：https://elicit.com/ 。借鉴逐项文献抽取、可检查的来源和研究表格/多步工作流。页面上关于准确率或速度的营销数字不作为本项目优势或效果证据。
- Semantic Scholar：https://www.semanticscholar.org/product 。借鉴日期筛选、文献分类与发现工作流。本项目没有因此获得其全库数据，也没有接入其全部功能。
- Zotero 官方阅读器与分类文档在本环境出现 TLS 连接失败；OpenAI 官方模型/价格文档出现 403 或 TLS 失败。没有据此声称核实最新定价、最新 GPT 型号或完成 Zotero 功能对照。

当前特色仍需与人工阅读、普通 RAG 问答、仅文本版本 diff 比较，测量错误结论、漏答、版本影响误报/漏报和核验时间。只展示界面不能证明这些优势。

## 真实测试及失败记录

1. 当前完整后端回归 **99 项通过**（`artifacts/product-audit/backend-tests-final.log`）；新功能测试覆盖原文/元数据保留、账户隔离、书签页码、译文与草稿冲突、校正历史、术语与代码公式保护、散点图/对数合法性、虚构列拒绝、缓存失效与来源标识、相邻证据、矩阵版本依赖去重。
2. 前端 TypeScript 与生产构建通过。仍存在 Mermaid 等较大分包的体积提示，不影响本次构建成功。
3. Chrome 实测正文搜索、页码跳转、书签刷新保留、文献分类界面、术语表编辑、年份控件、真实散点/对数图渲染及下载入口。又实测矩阵表格、草稿保存导出和点击引文返回 PDF。两个浏览器报告均无页面 JavaScript 错误。
4. 真实本地模型将“双对数散点图”正确映射为 step/loss、scatter、log/log，并渲染图表。
5. 真实翻译样例保留了自注意力术语、8、0.001、代码片段、否定和可能性语气。一个样例通过不能推导整体翻译准确率。
6. 两篇论文 × 两个问题的矩阵首次有 BERT 漏答：重排只选定义段，遗漏紧接的规格段。修复后两篇均有规格回答；两篇均未虚构碳排放。原始结果 `live-first-run.json` 和复测 `matrix-after-context-fix.json` 分开保存。
7. 上述复测依然有语义覆盖限制：泛问“主要模型”时 BERT 回答只覆盖 BASE，Transformer 层数未明确编码器/解码器。它证明取证链和缺证据行为可运行，不证明所有变体或所有条件完整。需要更精确的问题拆解与独立标注继续评估。
8. 首次写作输出过于笼统，评估字段还变成字典字符串；保存于 `writing-live.json`。据此改为严格实验设计字段。结构化复测仍出现 WikiText/GLUE 与 BLEU 错配、计时条件缺失以及建议混入背景；完整保留在 `writing-after-structure-fix.json`。进一步将背景改成原文摘录，并增加任务指标、划分、计时、显著性等可检查的风险提示。最终实测另存 `writing-final-live.json`，不覆盖失败。最终方案仍出现“固定 d_model/d_k/d_v 同时改变头数”和直接更改预训练头数的问题；已补维度和权重兼容检查，对既有方案读取时补充最新提示，原稿不改写。`writing-final-assessment.json` 保留了风险列表。提示用于发现风险，不能替代科学审查。
9. Crossref 实时查询年份 2020—2026，第一页与第二页均 HTTP 200、各 12 条；完整记录 `discovery-live.json`。不能据此认为 arXiv 限流问题消失。
10. 本轮首个浏览器脚本使用了错误的模块名称“阅读与翻译”，实际是“双语与引文”；修正脚本后通过。首次失败报告也保留。

另运行 3 个已有开发问答回归：训练序列/上下文区分、GPT-1 与 BERT-LARGE 规格、不可回答的 GPU 序列号，机械检查均通过，见 `qa-regression.json`。原始回答仍有冗余重复，未将此计作语义质量满分。用户原先的页码、Enter/换行/IME、教程与移动阅读布局在 `scripts/check_usability.mjs` 中再次全部通过。

所有上述题目和检查由开发代理编写，不是官方题集结果，也不是独立研究者盲评。测试数量不等于模型准确率。

## 仍不能宣称完成的部分

- 全领域、复杂扫描、跨页表格、多级公式的稳定语义解析；当前仍要回到原图校正。
- 自然语言问题的完整消歧、多个规格的稳定覆盖；领域翻译、科研推理、写作质量的独立盲测。
- 更强本地模型与 GPT 的实际同题比较；尚未完成模型升级或云服务接入。
- 全量学术库、所有论文合法全文获取、外部数据源不间断可用。40 份只用于当前本地研究和验收。
- 研究方案的科学价值与创新性判断，方案中的实验尚未开展。图表还不支持任意复杂科学制图、自动判断因果/显著性或完全自动的误差棒统计流程。
- 持续 24/72 小时运行、容器实机验收、公网评审部署、独立用户使用研究与完整答辩材料。没有执行就不标记已验收。

## 下一阶段的质量门槛

先冻结含正确答案、证据页、适用条件和不可回答项的任务集，再比较系统与基线。重点分开记录：检索漏证据、生成错误、拒答过多、单位/条件遗漏、版本归属错误、翻译改变否定、图表参数误解。模型与提示调整后，在新样例上检验是否改善，保留失败，不把调过的题目称为独立准确率。

待验证的产品演示路线：选择论文 → 提出复现问题 → 形成带缺项的证据矩阵 → 制定可执行实验设计 → 填入真实实验 CSV → 生成可复现图表 → 保存带引文草稿 → 加入新版本并找出需要重新核验的格子/结论。用一条完整任务证明价值，比堆积页面更重要。
